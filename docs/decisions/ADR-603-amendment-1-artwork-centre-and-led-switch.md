## ADR-603 Amendment 1 - Choose an artwork centre and keep a separate LED On/Off control

**Status:** Accepted by the maintainer's explicit requests on 2026-10-18. The maintainer chose to keep both manual artwork centring and automatic whole-job centring after Frame, and requested that the LED remain on after centring until switched off. Amends ADR-603 and the manual-button restriction in ADR-605 Amendment 1. Software and simulator evidence do not establish physical pointer alignment.

**Decision.** Rename the manual action **Artwork centre & LED**. One selected artwork centres directly; a selected group remains one artwork. Several selected artworks expose an inline **Artwork to centre** chooser. Choosing a target sends no movement; the explicit button moves to that artwork only. The chooser keeps the canvas selection and clears its choice when the selection changes. Registration boxes are not artwork targets, and separate jig copies remain separate choices.

Absolute Coords retains direct canvas/bed positioning when no Frame exists. With a completed ordinary Frame, use the selected artwork's evaluated geometry in the exact prepared scene and its captured placement translation. This includes Print and Cut and variable artwork transformations. User Origin, Verified Origin and Current Position require that captured Frame because the canvas alone does not locate the artwork on the board. A selected object absent from the framed output cannot be given an invented output position. Device-origin mapping, the captured job offset, current matching work offset and the configured pointer offset determine the native head target. Do not recompute the origin around the chosen subset.

The controller queue fence and owned positioning transaction recheck the chosen IDs, project, placement, Frame and controller identity before issuing commands after an asynchronous wait. Deselecting/deleting the target or changing placement cannot redirect a pending request. Verified travel retains the original completed Frame candidate and captured Current Position origin under ADR-605 Amendment 1; Start therefore retains the framed job's placement.

**LED controls.** Explicit **LED on** and **LED off** controls sit beside the centring action. They switch only the configured separate light, with no head movement, coordinate reset or selection requirement. On follows the existing controller ownership, fresh Idle, cutting-tool-off, command acknowledgement and configured-output rules. Off retains the captured output mapping when the profile changes, so it can switch off the output previously enabled. The ADR-612 Marlin Fan-mosfet exception remains absolute: that dialect has no positioning-light controls and sends no light command, including a captured Off. Off remains available for a configured light even when tracking is false after reset, because the controller does not report the actual optical state.

Successful manual centring, automatic after-Frame centring and manual On leave the LED on without an expiry timer. The On control reflects the app's command tracking, not an optical sensor. Existing controller cancellation, reset, disconnect, alarm and operation-ownership rules still apply. No universal hardware command, new physical alignment, entitlement gate or Start policy gate is introduced.

**Verification.** Focused unit and controller-simulator tests cover individual versus grouped/whole-job targets, all four placement modes, all device-origin orientations, offsets and evaluated geometry, stale choices and asynchronous cancellation, actual Current Position Start preservation, persistent On/Off without motion, captured-map Off after profile edits and all five live controller families. Browser interaction tests use production controls with an in-memory simulated transport at narrow and desktop widths, proving that choosing alone does not move, only the chosen artwork centres, and On/Off does not recenter.
