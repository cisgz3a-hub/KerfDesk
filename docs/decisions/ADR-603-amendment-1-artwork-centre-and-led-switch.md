## ADR-603 Amendment 1 - Choose an artwork centre and keep a separate LED On/Off control

**Status:** Accepted by the maintainer's explicit requests on 2026-10-18. The maintainer chose to keep both manual artwork centring and automatic whole-job centring after Frame, and requested that the LED remain on after centring until switched off. Amends ADR-603 and the manual-button restriction in ADR-605 Amendment 1. Software and simulator evidence do not establish physical pointer alignment.

**Decision.** Rename the manual action **Artwork centre & LED**. One selected artwork centres directly; a selected group remains one artwork. Several selected artworks expose an inline **Artwork to centre** chooser. Choosing a target sends no movement; the explicit button moves to that artwork only. The chooser keeps the canvas selection and clears its choice when the selection changes. Registration boxes are not artwork targets, and separate jig copies remain separate choices.

Absolute Coords retains direct canvas/bed positioning when no Frame exists. With a completed ordinary Frame, use the selected artwork's evaluated geometry in the exact prepared scene and its captured placement translation. This includes Print and Cut and variable artwork transformations. User Origin, Verified Origin and Current Position require that captured Frame because the canvas alone does not locate the artwork on the board. A selected object absent from the framed output cannot be given an invented output position. Membership follows the captured scene’s canonical enabled-operation and sub-operation rules; a chosen group containing a non-output member is rejected as a whole. The framed centre uses only enabled output paths within each member; disabled sibling paths inside an imported artwork cannot shift the marker. Direct Absolute positioning before Frame retains the whole-artwork canvas centre. Transient camera and second-pass Frames do not enable this ordinary artwork action. Device-origin mapping, the captured job offset, current matching work offset and the configured pointer offset determine the native head target. For a captured Verified Origin whose native offset is unknown, the prepared work target is used directly: transform the LED offset as a vector (transform(offset) minus transform(zero)) and subtract it in work axes. Require direct finite work-position reports, normalized to millimetres, for relative travel and final settlement; never invent a machine origin. Completed Absolute and eligible Current Position Frames retain their previously captured assumed-zero placement under ADR-375, using work reports when available or machine reports under that same assumption, with the existing unverified-position warning. This does not create an assumption for a new custom origin or write a fabricated WCO. Do not recompute the origin around the chosen subset.

The controller queue fence and owned positioning transaction recheck the chosen IDs, project, placement, Frame and controller identity before issuing commands after an asynchronous wait. Deselecting/deleting the target or changing placement cannot redirect a pending request. A one-way spatial-change observer spans controller waits, so a geometric edit followed by Undo cannot restore the proof temporarily cleared for travel. Power, speed and label-only edits retain spatial evidence under ADR-565; replacing the document still cancels the request. Verified travel retains the original completed Frame candidate and captured Current Position origin under ADR-605 Amendment 1; Start therefore retains the framed job's placement.

**LED controls.** Explicit **LED on** and **LED off** controls sit beside the centring action. They switch only the configured separate light, with no head movement, coordinate reset or selection requirement. On follows the existing controller ownership, fresh Idle, cutting-tool-off, command acknowledgement and configured-output rules. Standalone On preserves unrelated coolant, air and fan accessories; only centring uses the complete Frame accessory-off sequence. Off retains the captured output mapping when the profile changes, so it can switch off the output previously enabled. The ADR-612 Marlin Fan-mosfet exception remains absolute: that dialect has no positioning-light controls and sends no light command, including a captured Off. Off remains available for a configured light even when tracking is false after reset, because the controller does not report the actual optical state.

Successful manual centring, automatic after-Frame centring and manual On leave the LED on without an expiry timer. The On control reflects the app's command tracking, not an optical sensor. An unsupported-command response (`error:20`) from the same owned GRBL-family exchange can clear On tracking because the preceding Off was acknowledged. Malformed responses, system faults, Marlin/Smoothieware errors and lost acknowledgements retain the captured Off mapping because they do not prove the output stayed off. For centring travel, only a single native GRBL-family jog with a normalized travel-limit or unsupported-command refusal and a current Idle report can be classified as never started. Ambiguous faults or any reported Jog/non-Idle state use the existing owned Abort containment; failed travel still clears Frame. Existing controller cancellation, reset, disconnect, alarm and operation-ownership rules still apply. No universal hardware command, new physical alignment, entitlement gate or Start policy gate is introduced.

**Verification.** Focused unit and controller-simulator tests cover individual versus grouped/whole-job targets, all four placement modes, all device-origin orientations, offsets and evaluated geometry, stale choices and asynchronous cancellation, actual Current Position Start preservation, persistent On/Off without motion, captured-map Off after profile edits and all five live controller families. Browser interaction tests use production controls with an in-memory simulated transport at narrow and desktop widths, proving that choosing alone does not move, only the chosen artwork centres, and On/Off does not recenter.
