## ADR-597 - Consistent remote canvas and AI selection

**Status:** Accepted for the maintainer's 14 October 2026 request to upgrade MCP canvas selection and deselection, covering both mouse/touch controls and AI selection tools. Extends ADR-582 and ADR-584.

**Context.** The shared remote app replaced selection on each tap, did not support modifier-key or touch multi-selection, and lacked Select All and Escape. Rapid selection requests could race revisions and refreshes. AI clients had only replacement selection, requiring a complete client-side copy to add or remove an item. Native selections larger than the bounded remote projection were not explicitly identified.

**Decision.**

- The shared phone/MCP canvas offers Multi-select, Select all and Deselect. Shift/Ctrl/Cmd-click toggles a whole eligible artwork group; Multi-select provides the same action for touch. An ordinary click on an already-selected member keeps its multi-selection. Empty-space clicks clear an ordinary selection. Left-to-right marquee encloses artwork; right-to-left marquee crosses it; modifiers or Multi-select add the result. Hidden and locked artwork are excluded.
- Ctrl/Cmd+A selects all. Escape first cancels an active gesture, then an unapplied drawing, then selection. Text fields, contenteditable controls and open sheets retain their own keyboard handling. Right/middle-button drags pan. Gestures belong to their document revision, connection, view and editing state; changing those cancels the gesture before it can commit.
- The existing edit-scope `set_selection` gains optional `mode`: `replace` (default), `add`, `remove`, `toggle`, `all`, or `clear`. The first four require `artworkIds`; `all`/`clear` accept no target IDs or an empty list. Both single commands and atomic batches share the same preparation. Connected group units are processed once, independently of the desktop's local Edit-inside focus. Removing/clearing can release a now-hidden or locked selection.
- Selection remains bounded to 200 resulting artwork IDs, including group expansion; exceeding that limit refuses the entire request. `all` evaluates the authoritative document, not a partial workspace listing. Workspace responses advertise `selectionModes` and report `totalSelected`/`selectionTruncated`. The app cannot transform or incrementally replace a truncated selection as if it were complete.
- App selection writes are serialized and intermediate choices coalesced. Successive requests use the preceding confirmed revision, and stale reads cannot overwrite a newer choice. Failed revision checks refresh rather than replaying an intent against a changed document, and cancel dependent transforms. Drag previews leave canonical selection untouched; a committed drag selects its target and moves it atomically where supported, or chains a successful selection receipt on older desktops. Read-only inspection remains local across refresh. Model context reports the selection count, truncation and local/pending/desktop ownership; view-only app tools retain their existing authority.

**Unchanged.** PC approval and scopes, sharing opt-in, UUID replay, Undo, response bounds, Pro admission, the current output scope and Frame/Start rules remain unchanged. No machine command is delayed behind the selection queue; a settled selection receipt can supply its exact revision. Abort retains its immediate path.

**Consequences.** Updated desktop and service/app builds are needed for the new authoritative modes. Older desktops keep ordinary replacement selection; Select All uses a local list only when that list is complete. Source and browser-fixture verification do not qualify hosted MCP clients, physical phones or hardware.
