## ADR-567 - Connected laser execution power scale

**Status:** Accepted by the maintainer's explicit request that 100% power reach the connected controller's full commanded range, and authorisation to repair confirmed audit findings, on 2026-10-02. This amends the saved-profile interpretation of PROJECT non-negotiable 7 for connected GRBL-family laser output. Software evidence does not qualify physical or optical output.

**Context.** A saved profile can use S255 while the current controller reports $30=1000. Emitting profile-scaled S255 for 100% then reaches only part of that controller's commanded range. The reverse mismatch also makes low requested percentages reach much higher nominal power. A warning alone does not correct these executable bytes. Layers, per-object scaling and operation overrides describe percentages; they are independent of the controller's S-word range.

**Decision.** Fresh laser output uses a positive finite $30 from a connected GRBL v1.1, grblHAL or FluidNC session only when its settings observation is stamped for that current connection epoch. The saved output profile must also use a GRBL-family dialect. Another controller family, missing observation, disconnected state, replacement-session observation or invalid range retains the saved profile assumption and discloses it. This does not issue a controller setting command, mutate the authored project, or replace the remembered machine profile. CNC spindle RPM and non-GRBL power dialects retain their existing contracts.

The shared preparation pipeline receives the effective S maximum and applies it to an execution copy before compiling or quantizing raster pixels. Save, Preview, ETA, Frame preparation and ordinary Start use that same range, including worker and variable-text snapshot paths. Preparation caches include the effective range. Execution archives retain the exact emitted bytes and execution profile, with current controller observations and the warnings shown. Unknown/offline exports state that their profile S range is assumed. Integer ranges preserve existing rounding. Fractional GRBL ranges retain their full-scale endpoint and use a virtual integer raster range before rescaling, so sub-unit maxima do not collapse every pixel to zero or one. Raster samples remain numeric Float64 values and do not impose a 16-bit S ceiling. Relative fractional precision is retained even below 0.000001, and emitted S words use ordinary decimal spelling rather than JavaScript exponent notation.

Start records the effective range, whether it came from current controller evidence or the profile, and the connection epoch of live evidence. It compares that binding again when affirming review and at the final synchronous wire authorisation. A changed range requires preparing and approving fresh output. An equal-value settings refresh does not change the executable scale. This is exact reviewed-output ownership, not an additional account, activation, controller-policy or ordinary Start gate.

The completed spatial Frame remains reusable when the footprint, placement and coordinate basis are unchanged, under ADR-565. Power range changes alone do not revoke it. Other controller settings, including $31 and $32, retain their existing Job Review advisories. Realtime laser overrides retain the existing acknowledged reset to 100% before a fresh job. The one-second positioning mark and held Fire retain their separate consent, low-power cap and smaller-of-profile/controller range in ADR-566; normalising a job must not raise those positioning controls.

Frozen recovery and second-pass bytes are never silently rescaled. A saved job whose original scale differs from the currently observed $30 explicitly discloses that its original percentages do not describe this controller's full range. Second-pass review uses the sealed execution profile and captured review evidence for that warning; changed evidence is redisplayed and needs another affirmative confirmation. Its prior exact-byte and controller qualification contracts still apply.

Successful prepared output records power-scale version 2. An archived prepared record without that field uses historical version 1, which rounds vector power in its original S range and retains raw S spelling. Its streamed raster provider recipes recompile using that same historical quantization range; version 2 recipes use the virtual fractional range. Hydration carries the selected version through base emission, resume transforms and second-pass writer validation. The normalized version joins captured second-pass source metadata, so an in-place semantic version change invalidates a pending Worker result. Missing and explicit legacy version 1 share semantics; invalid null or unknown versions remain distinct. Unknown versions fail archive decode and hydration. Stored bytes and existing fingerprint/lineage checks remain exact. Non-GRBL output, including fractional Marlin inline profiles, retains its historical rounding and spelling through the shared emitter.

**Meaning of full power.** 100% requests the controller's maximum S command. M3 constant-power and M4 dynamic-power modes remain distinct. In M4 the firmware reduces instantaneous power with motion speed and turns it off while stationary; short moves and acceleration need not spend time at full PWM. Nonzero $31, configured PWM limits, firmware calibration, laser optics, material, focus and actual watts are not established by S-word equality. No controller mode, calibration or material recipe is invented to make a burn appear stronger.

Stock GRBL's [numeric parser](https://github.com/gnea/grbl/blob/bfb67f0c7963fe3ce4aaf8a97f9009ea5a8db36e/grbl/nuts_bolts.c#L20-L97) retains at most eight numeric digits, including leading zeroes, and accepts no exponent notation. Very small S words omit a leading zero when it would consume precision; this does not extend the firmware's own positive representability below `.00000001`, or qualify float/PWM precision. Stock settings reporting uses three decimal places, so tiny stored $30 values ordinarily report zero and use the disclosed profile fallback. Byte-spelling regressions with injected tiny observations establish software encoding, not that those observations can be recovered from stock firmware or that every tiny requested share reaches its PWM.

**Primary evidence.** [Stock GRBL settings](https://github.com/gnea/grbl/blob/bfb67f0c7963fe3ce4aaf8a97f9009ea5a8db36e/grbl/settings.c) stores $30 as a float; [its PWM conversion](https://github.com/gnea/grbl/blob/bfb67f0c7963fe3ce4aaf8a97f9009ea5a8db36e/grbl/spindle_control.c) saturates the maximum command and treats the minimum separately. [GRBL motion power adjustment](https://github.com/gnea/grbl/blob/bfb67f0c7963fe3ce4aaf8a97f9009ea5a8db36e/grbl/stepper.c#L877-L896) and [laser-mode documentation](https://github.com/gnea/grbl/wiki/Grbl-v1.1-Laser-Mode) explain dynamic M4. [grblHAL settings](https://github.com/grblHAL/core/blob/d7aaee3d84b1e7010f075d395206afff038d7379/settings.c) declares maximum spindle speed as decimal. [FluidNC's compatibility settings](https://github.com/bdring/FluidNC/blob/fdc17a2c/FluidNC/src/SettingsDefinitions.cpp) report the active spindle speed range rather than an independently writable GRBL $30.

**Verification required.** Both mismatch directions; M3/M4 and GRBL-family output; fractional percentages and S maxima below one; S maxima above 65535; per-object and per-operation overrides; a low-power raster pixel that would vanish if quantized first in the old range; snapshot/worker cache identity; connected Save, Preview and Start parity; unchanged authored profile; accepted-run archive bytes; missing, invalid, disconnected and replacement-session settings; range changes during review, durable handoff and final transport assertion; unchanged spatial Frame reuse; equal-value refreshes; frozen archive disclosure; unchanged capped mark; and retained machine defaults versus new-job settings. Hardware, optics and customer-profile upgrade qualification remain separate.
