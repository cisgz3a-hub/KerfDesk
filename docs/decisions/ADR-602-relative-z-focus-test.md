## ADR-602 — Relative Z focus-test samples

**Status:** Implemented under the maintainer's explicit 2026-10-16 request to implement Focus Test. Software verification and physical-machine qualification remain separate.

Focus Test previously advertised a disabled placeholder. It now generates ordinary laser Line artwork with one named operation per represented Z offset. The operation retains `focusTest.offsetMm` and `travelFeedMmPerMin`, and compilation carries that intent into cut groups. Reordering samples or selecting only some samples does not accumulate Z motion: each completed sample moves from the starting physical focus by its own relative offset and returns by the opposite offset. The project uses schema 18 so older readers cannot silently omit the Z semantics. Existing projects migrate without inventing focus intent.

The dialog supports 2–101 samples, validates finite values and rejects offsets that collapse to the same 0.001 mm output coordinate. Names and the displayed list use the represented values. Relative G91 Z motion uses an explicit positive feed capped by the selected profile's feed ceiling; G90 is restored before any XY burn. No G92, probing, homing, work-offset writing or assumed absolute Z datum is introduced. The emitter uses existing power scaling, origin transformation, dialect, tool-off travel and current exact-program preparation.

Every Z move follows M5 and carries S0. Under constant-power operation, an actual laser-off XY move inside the existing sample envelope precedes a planner-draining M5, avoiding a stationary powered stop at the burn endpoint. Each sample's laser-off return remains inside its existing XY envelope. Existing mode and coolant transition ownership remains intact. Focus output currently supports GRBL, grblHAL and FluidNC; unsupported dialects and non-Line operations fail as unconstructable focus output rather than silently dropping Z intent.

Sample labels are retained operation names and are not burned into the material. The 2D planner estimate excludes the additional Z moves and laser-off returns; the dialog and Job Review disclose this. Inspect G-code (3D) parses the exact emitted program for the full 3D motion and playback estimate.

This uses the ordinary document, Preview, Save G-code, Frame, Job Review and Start path. No alternate transport or direct hardware action is added. The ADR-565 completed-frame contract remains intact. Travel-feed edits retain spatial Frame identity while changed offsets invalidate it. Focus artwork switched to CNC is an unconstructable mixed-mode program and receives a canonical compile-integrity failure. Interrupted-program recovery cannot reconstruct the original relative physical Z datum and refuses line-resume for Focus programs; restore the physical focus and use ordinary Frame/Start for a complete test instead. Job Review discloses the relative Z range, unconfirmed Z capability, configured travel exceedance, and the fact that Frame traces XY only. These are warnings, not extra Start gates. The app cannot infer physical starting clearance from configured travel. An aborted/interrupted job may leave Z displaced; the operator must establish actual position before continuing. This is a focus comparison, not autofocus, and no generated material outcome is claimed.

Research: [GRBL v1.1 Laser Mode](https://github.com/gnea/grbl/wiki/Grbl-v1.1-Laser-Mode) establishes that M3 can remain powered at rest, spindle state changes stop motion, M4 stops dark, and a motion with S0 turns power off without an unnecessary stop. [GRBL supported commands](https://github.com/gnea/grbl/wiki) documents G90/G91, G21 and G94. Existing `grbl-output-cursor.ts` records corresponding GRBL, grblHAL and FluidNC parser/controller implementation evidence. These sources support command semantics, not qualification of the user's controller wiring or Z travel.

Verification covers finite/range/count/precision boundaries, deterministic 101-sample stress output, per-sample net-zero Z, laser-off Z moves, absolute XY burns, feed capping, constant-power dark transitions, unsupported controller/mode rejection, schema round-trip and malformed input, UI generation and one-step Undo. Browser/computer-use and hardware results belong in the accompanying quality register.
