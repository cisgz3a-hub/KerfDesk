## ADR-569 - Separately approved Jog, Frame and Start through MCP

**Status:** Accepted for the maintainer's explicit request on 4 October 2026 to control Jog, Frame and Start from a phone and MCP. Extends ADR-564/568. Source, hosted service, installed release, client and physical-machine qualification remain separate.

**Context.** Workspace editing permission does not authorise machine movement. The maintainer now requests actual controls with an easy interface. Long Frame and job preparation cannot be represented by a twenty-second RPC that reports a timeout as completion, and uncertain network retries must not repeat physical actions.

**Decision.** Add a distinct `control` pairing permission and `kerfdesk:control` OAuth scope. Every controlled connection requires viewing permission and explicit approval on the PC for machine control. Editing is independent. Existing read/edit approvals gain no movement permission. The PC approval choices for editing and machine control start unchecked; the machine-control description names Jog, Frame, Start and Abort and explains their physical effect. UI hints and tool annotations grant no authority. Preserve OAuth resource/audience binding and current native approval checks.

The public tools add `get_machine_status`, `get_control_operation`, `jog_machine`, `frame_job`, `review_machine_job`, `start_job` and `abort_job`. Jog is one discrete axis/direction/step command, with the desktop's real axis support, origin direction and feed limits. It uses the existing jog implementation. Frame uses canonical tool-off preparation and completed-Frame evidence. Machine connection changes, homing, raw G-code/console commands, arbitrary laser firing, shell commands and file access remain outside this permission.

Remote Start uses the ordinary flow-owned Job Review, preparation, acknowledgement, exact-program recheck and one-use execution claim. `review_machine_job` prepares an owned review with a one-use handle; `start_job` explicitly confirms that handle. The remote UI shows the canonical review and acknowledgement before confirmation. Changed program or review facts require a refreshed review and another affirmative action. A clean completed Frame for unchanged placement remains the sole ordinary Start policy gate under ADR-565. Policy findings remain warnings. Client authorisation is access control, not a new machining policy, and this extension adds no licence or activation gate.

Control tools return a bounded operation receipt promptly. Status reads distinguish accepted, preparation, review pending, streaming and observed completion; a controller acknowledgement alone is not movement completion. The logical operation ID is the caller's UUID. The relay durably reserves each client/lease action ID and canonical payload digest before dispatch. Same ID with different arguments is rejected; a lost result leaves that ID consumed and its outcome uncertain. Active-lease records are bounded without deleting a replay tombstone to admit more work. Capacity exhaustion requires fresh pairing. Revocation invalidates the old lease and its action records. The ledger stores action identifiers, digests and bounded outcome metadata, never artwork, text or executable G-code.

Accepted work captures the client, renderer session and live machine authority independently of its completed RPC. Permission loss, session replacement or disconnect prevents subsequent machine dispatch. Cancellation applies only to the exact owned preparation or jog/Frame; it cannot stop a replacement controller. A normal job already handed to the streamer retains its committed receipt and ordinary desktop run lifecycle. An approved operator may explicitly invoke the canonical Abort action. Abort ingress remains available while an ordinary request is pending and does not depend on a stale artwork revision. Remote Abort requires a working connection and is not a physical emergency stop.

The phone and portable MCP App provide a **Machine** view with live labelled position, discrete jog controls, Frame, Job Review and Start, plus independently reachable Abort. Missing permission/session/axis evidence disables physical actions. Status polling does not replace workspace or numeric drafts. An uncertain result offers **Check status** without automatically creating another movement request. Machine actions are described as consequential writes with explicit destructive and non-idempotent annotations; they operate only on the bounded approved PC.

**Consequences.** The user can approve machine control without artwork editing. Both the matching desktop build and relay must support this protocol; old clients fail closed for machine commands. Native simulator and browser tests do not qualify a physical laser or spindle. The desktop release cadence is governed by [ADR-561 Amendment 4](ADR-561-amendment-4-ten-pr-release-batches.md), including its explicit early-release override.
