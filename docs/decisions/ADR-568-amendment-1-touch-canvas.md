## ADR-568 Amendment 1 - Usable touch canvas and truthful image placement previews

**Status:** Accepted for the maintainer's MCP canvas repair requested on 5 October 2026.

The phone and embedded MCP canvas keep artwork visible when opening creation or numeric properties. Primary selection, navigation and creation actions remain beside the canvas. A shared local viewport implements mouse/finger pan and two-finger pinch around the gesture midpoint. Completed drafts survive local navigation; a second finger cancels an unfinished edit stroke before navigation begins. Applying a draft still invokes one canonical, revision-fenced, idempotent PC mutation. Permission revocation, document changes, invalid mapping and page teardown retain their existing refusal/cancellation contracts. Viewport navigation itself grants no authority and sends no mutation.

The default supported PNG remains bounded, tied to the accepted revision and mapped through its exact returned viewport. Its transient replacement after a PC edit does not reset zoom. Phone and embedded touch implementation are generated from the same sources and checked for parity before build and deployment. Numeric text and rectangle creation are directly accessible in both clients; numeric properties provide alternatives to drag editing. Rich canvases should use host-supported expanded/fullscreen presentation where available; unsupported hosts keep the ordinary embedded view.

ADR-568's blanket raster-scene exclusion is amended only for **explicit partial previews**. A visible raster image or relief may contribute its actual transformed placement footprint, rendered as a dashed frame together with real vector paths. The ready result must explain that image pixels are omitted and frames show placement only, and clients must display that explanation. This is not an accurate image/burn preview. The complete visible placement extent is included in bounds and coordinate mapping. Unsupported vector geometry and exceeded size/complexity budgets still refuse the whole preview; contributing geometry must never silently disappear.

The footprint projection reads only the existing placement dimensions and transforms. It must not read image sources, external URLs, file paths, image assets, luma arrays or masks. Complete raster compositing and a bounded vector scene protocol require their own reviewed implementation. This amendment introduces no new sharing preference, remote network capability, licence gate, machine action, Frame or Start policy.

Evidence remains separate: fixture Chromium touch and renderer tests do not qualify a physical phone, actual ChatGPT host, installed desktop update or physical machine. The hosted phone UI can update independently; renderer preview changes require a desktop release under ADR-561 Amendment 4.
