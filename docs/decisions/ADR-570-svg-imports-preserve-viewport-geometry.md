## ADR-570 - SVG imports preserve viewport geometry

**Date:** 2026-10-07

**Status:** Accepted. Amends ADR-046's physical-size mapping and extends ADR-358 Amendment 2's visible-artwork clipping.

**Context.** Competitor-derived audit I1 reproduced a root SVG square becoming a rectangle because the importer always used independent X/Y scales. The existing test encoded that result without requesting `preserveAspectRatio="none"`. A nonzero root viewBox origin also shifted physical artwork instead of mapping it into its viewport. I2 reproduced invisible artwork outside nested SVG and symbol viewports importing as executable geometry because their overflow clipping was ignored. Browser rendering also confirmed that a clip directly on a viewport element must use its content coordinate system.

I3 reproduced supported primitive percentage lengths importing as their numeric prefixes: a rectangle at `x="25%"` in a 200-unit viewport imported at 25 instead of 50. The same error affected shapes in clip definitions and `<use>` positions. Reused symbol geometry also needs its active instance viewport when its object box is measured; the definition's DOM ancestry cannot supply a differently sized instance's context.

**Decision.** A root with a valid viewBox and at least one positive declared physical dimension maps its viewBox into a millimetre viewport using SVG's `preserveAspectRatio`: default `xMidYMid meet`, explicit alignment/meet/slice, and independent stretching only for `none`. A missing physical axis is inferred using the viewBox aspect ratio. Geometry and fragment bounds share this mapping. Zero-sized viewBoxes or declared dimensions render no artwork.

ViewBox-only files keep the documented one-user-unit-per-millimetre convention, including their coordinate origin. Files without a viewBox keep CSS pixels at 96 DPI. This changes import fidelity and adds no entitlement, Frame, Start, or controller-setting gate; current spatial Frame evidence and exact executable review remain governed by ADR-565.

The I1 follow-up preserves ADR-358's artwork scene-coordinate round trip without changing standard viewport mapping. New KerfDesk artwork exports write root-only `data-kerfdesk-artwork-origin="v1 x y"`, where `x` and `y` are the exact page origin in millimetres after outward grid rounding. The importer applies that explicit translation after normal root mapping, to both geometry and fragment bounds; viewport and owned image clips compose in the same frame. The format accepts only version `v1` and exactly two finite SVG numbers. Missing, malformed, nonfinite and unknown-version values leave the normal mapping intact. Human-readable titles/descriptions never select a mapping convention, and metadata cannot enable a disabled root.

This metadata affects KerfDesk's artwork coordinates only. Native SVG rendering retains the same physical page, viewBox and appearance. Older exports, and files whose metadata an external editor removes, use standard physical-root mapping and cannot automatically recover the original scene coordinate frame. Their relative registration and physical size remain available. This introduces no controller placement command or import-policy gate.

Viewport `overflow` joins the existing clip chain as the viewport's exact rectangle, transformed from parent space before the viewBox mapping. Nested `<svg>` and instantiated `<symbol>` default to hidden overflow; a standalone root defaults to visible. Explicit `hidden` and `scroll` clip, while `visible` and `auto` render overflow. Presentation attributes, supported stylesheet rules, inline style, and CSS-wide inheritance/initial keywords resolve through the existing cascade. An explicitly visible child retains any ancestor clip.

Viewport clips intersect ordinary clip paths for vector fills, ordered cut lines, and owned image clips. Fully contained native curves stay unchanged; cut curves use the existing 0.025 mm tolerance. A clip owned by a viewport uses its mapped content space. Its object bounding box is measured from the instance's complete child geometry before viewport or other clipping, with the instance viewport passed explicitly to the bbox reader and cache. Inherited clips retain their owner's coordinate system. Clip rectangles never become separate imported artwork.

Supported primitive geometry attributes and `<use>` positions resolve percentage X coordinates, widths and X radii against the nearest viewport's width; Y coordinates, heights and Y radii use its height. A circle's percentage `r` uses the normalized diagonal, `hypot(width,height)/sqrt(2)`. With a viewBox, these references are its user-coordinate dimensions under meet, slice and none alike. Without a viewBox, they are the viewport's absolute size in CSS user units, before the existing 96-DPI millimetre conversion. Group and shape transforms do not establish percentage viewports. Corner radii resolve before the existing auto-copy and side clamping; native curve and closure behavior is retained.

The active viewport travels with instantiated artwork and object-box measurement. Bounding-box and clip cache keys distinguish instance viewport dimensions and content-versus-placement measurement. Clip children resolve percentages in their definition viewport, including a clip `<use>`'s geometry context; the referencing artwork's box is an additional mapping, not a 1-by-1 percentage viewport. Numeric fractional object-box coordinates are unchanged. The convex containment proof, general region engine, ordered line clipping and owned image clips consume the same resolved clip geometry.

This repair retains numeric and supported absolute-length behavior and the existing numeric-prefix fallback for unreadable attribute units. It does not add CSS geometry support: CSS-only clip geometry still refuses under ADR-358 Amendment 2. Image positions and dimensions still require usable absolute lengths; unsupported percentages remain disclosed skipped images under Amendment 3. Root transforms, CSS unit policy, ordinary import placement and machine policy are unchanged.

**Verification.** Fallback and worker regressions exercise default aspect, explicit stretching, nonzero origins, alignment, slice, inferred axes, disabled roots, and the existing millimetre convention. Viewport clipping regressions cover default/explicit/CSS overflow, explicit root clipping, transformed and intersected nested viewports, symbol and SVG instances, pre-clip object boxes, wholly hidden artwork, boundary lines, contained/crossing curves, and transformed embedded images. Independent browser rendering supplied the audit's geometry and own-clip composition oracle. Source/test results do not qualify a physical machine or released build.

Chrome 153 confirms viewport-owned user-space clip placement and differently sized object-box instances. It drops the same element's implicit overflow clip in the object-box and sliced-symbol controls: the object-box example paints `x=20..40, y=10..50`, where SVG 2's viewport intersection keeps `x=20..30, y=10..30`. Those intersection expectations follow the specification and are not browser-matched evidence. The own-clip coordinate-space correction and this rendering discrepancy are separate observations.

Artwork-origin regressions cover fallback and streamed-worker sanitization, invalid/unknown metadata, selected vector holes, negative image coordinates with unequal mirrored scale, local image clips, translated root clipping, and the legacy export limitation. The existing scene-position round-trip expectations remain intact. Browser comparison of actual exporter output with its origin metadata removed checks that this private translation does not change native rendering.

Percentage regressions exercise both sanitized fallback and streamed-worker paths, each with 32 formerly failing percentage cases and 12 passing controls. They cover primitive axes and diagonal radii, root and nested aspect mappings, nearest viewports, no-viewBox 96-DPI conversion, signed/exponent coordinates, use positions, independently sized instances and pre-clip object-box caches, definition-context clips, curved regions, cut lines, contained curves and the explicit CSS/image boundaries. Chrome 153 supplies independent primitive bounds and painted-clip controls. A numeric circle control confirms that a fractional radius can use eight cubic pieces in the existing converter; the regression verifies its four geometric quarter endpoints and closure without fixing the number of pieces.
