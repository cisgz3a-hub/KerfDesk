## ADR-599 - Board layouts preview their footprints and jig edits carry artwork

**Status:** Accepted under the maintainer's instruction to implement the Registration Jig and Place Board fixes and upgrades and open a PR, 2026-10-16. Amends ADR-057 and ADR-124/125/126. Software verification does not qualify physical registration.

**Context.** Known-size rectangle entry was offered after two or three captures but refused by the commit validator. Array could produce an oversized copy when none fit and silently reduce requested counts. Jig grid replacement moved outlines while leaving linked artwork behind. These behaviours made repeatable placement harder to understand.

**Decision.**

1. A known-size rectangle can use its first captured origin after one, two or three captured corners. Entered dimensions replace partial measurements. Four-point measurement remains a separate path. Controller-session, trusted-position, work-origin and capture-session checks remain authoritative.
2. Place Board previews array footprints and the resulting count before applying. Preview and application use the same pure plan. A layout with no fitting copies returns no edits, rather than placing an oversized object. Explicit counts disclose requested versus placed copies and existing responsiveness limits. Spacing can be shared or independent on X/Y, with an edge margin in millimetres.
3. Round-board arrays can use rows contained by the circular boundary, checking every rectangular artwork-footprint corner, or use the conservative inscribed square. Bounded row-count candidates include a centred single row. This is a deterministic layout heuristic, not a claim of optimal nesting or contour-based packing.
4. Place Board fitting offers an explicit edge margin and either proportional fitting or centring at actual size. Keeping size reports a margin overrun without resizing. Round boards use a conservative circumscribed radius for artwork bounds; a verified canonical ellipse can use its major radius. A saved shape tag alone is insufficient to take that optimisation. Existing no-options store callers retain their previous proportional-fit behaviour.
5. Replacing a jig grid carries each linked artwork instance by its outline-centre displacement, preserving its exact size, rotation, mirror and local offset. Membership comes from persisted/legacy identity, never from geometric overlap. New positions start empty. This is fixture relayout, not live propagation of arbitrary source-artwork edits.
6. Shrinking an occupied jig set exposes a keep/remove choice. Keep retains object IDs, coordinates and external links, clears copy ancestry and keeps an explicit retired-slot identity to prevent legacy-ID inference from reattaching it. Such artwork can still output on enabled operations. Remove deletes the chosen members and cleans groups/order as one undoable edit; retained relief dependencies are preserved rather than silently broken. Undo restores the complete previous project.
7. Exact artwork-size controls also support a single linked jig. Discovering a single instance does not change ordinary single-jig operation scheduling.

**Boundaries.** Captured-board ownership stays exclusive to Place Board. This change adds no machine commands, Start gates, licence requirements or physical verification claims. Frame and Start continue to use the current spatial evidence and exact executable review under ADR-565. Tilted rectangle registration, persistent fixture recipes, personalised jig batches and silhouette fixture generation remain separate work; this change does not represent the broader concept preview as implemented.

**Verification.** Regression coverage exercises partial-capture entry and stale epochs, preview/application agreement, zero-fit and count limiting, circular containment, exact fit and keep-size, legacy identities, linked grid changes, removal choices, dependency preservation, undo and compilation ordering. Browser checks inspect the rendered controls and layout; hardware qualification remains separate.
