## ADR-605 Amendment 1 - Position the LED at the framed artwork centre in every Cartesian placement mode

**Status:** Accepted by the maintainer's explicit approval on 2026-10-18. Amends ADR-605 and the positioning-light exception in ADR-565. Software verification does not establish physical LED alignment.

**Request.** After Frame, the separate LED must automatically show the centre of the artwork where it will be on the board. The maintainer explicitly approved extending this to User Origin, Verified Origin and Current Position while preserving the placement captured by Frame for Start.

**Decision.** With the configured per-machine **Centre & LED after Frame** setting enabled, a clean ordinary Frame may centre the LED in Absolute Coords, User Origin, Verified Origin or Current Position. The target comes from the completed job's prepared artwork bounds, including its resolved placement, plus the controller work offset. The configured pointer offset is applied in bed axes. Current selection, output-disabled artwork and laser-off scan runways do not replace the framed artwork bounds. The manual selection-centre button is extended separately by [ADR-603 Amendment 1](ADR-603-amendment-1-artwork-centre-and-led-switch.md), which retains both options. The setting remains opt-in; no light commands, offsets or hardware defaults are invented.

The existing controller queue fence must settle Frame's last reply before LED travel starts. Immediately before dispatch, the same completed Frame, project, placement, cancellation epoch and controller coordinate identity must still apply. Transient camera and second-pass permits cannot use this ordinary-artwork action. Missing acknowledgements or changed evidence send no positioning command.

After verified beam-off LED travel, retain the completed Frame's original candidate and resolved job origin, and rebase only the observed controller position. A Current Position candidate must contain a finite captured X/Y origin. Start already prepares from that captured origin and checks the newly prepared bounds and placement against Frame, so moving the pointer does not relocate the cutting job. An interrupted or failed move, artwork or placement edit, a replacement session/origin, incomplete evidence or a later ordinary jog still invalidates Frame under the existing rules. This adds no Start policy gate and does not operate any physical machine during verification.

**Verification.** Regression coverage exercises real Frame and LED transactions across all five live controller families and all four placement modes, with nonzero work and LED offsets and selection different from enabled output. It checks the final native target, cutting-beam-off movement, preserved Frame candidate, fresh Start preparation at the captured origin and unchanged artwork/motion bounds. Current Position cases also execute the ordinary Start flow on each controller simulator, check that the exact prepared program is streamed once and retains the original origin in its run archive, and verify that later edits (even undone), jogs and resets revoke Frame. Additional cases cover mirrored axes, cancelled Frame, a deliberately held Marlin final acknowledgement, stale coordinate/session evidence, failed moves and explicit opt-out.
