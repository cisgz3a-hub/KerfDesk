# Released CNC and executable-output audit, 9 October 2026

The audit independently examined the source used for KerfDesk desktop 1.0.13: commit `e34ad795e1e6d8dad256d106e41e9b3a8f335331`, tree `075d0ca4fb817f1f947e7a7a931086a5694e3932`. The desktop publication workflow [37834306969](https://github.com/cisgz3a-hub/KerfDesk/actions/runs/37834306969) was successful. This audit qualifies software behaviour at that source and the local candidate; it does not qualify the installed executable or a physical machine.

Eight reproducible product defects were repaired, together with one internal numerical weakness. Baseline failures were saved before repairs. The dirty primary checkout and other audit worktrees were preserved.

A second review caught two candidate-only regressions before final verification. Inverting a concave ruled strip can have two valid answers even when the original diagonal triangles have the same orientation; all four corner Jacobians must have the same nonzero finite sign. A 1 mm CNC inside-profile registration jig can compile to no path, so its presence does not own a relative anchor. Frame uses the actual compiled registration bounds and falls through to the canonical full-scene placement anchor when those bounds are absent. Regression cases cover reflected folds, convex controls, inactive-side fixtures and the collapsed jig's 50 mm executable shift. These candidate-only findings are separate from the eight released defects.
A further independent review found a P2 candidate-only retention defect in the new per-scope Frame cache. With 1,600 visible vectors, actual Select, Undo, signature and Redo actions restore the same history-held project with 400 different scopes. The candidate retained 67,272,896 additional heap bytes after forced GC versus 87,080 for repeated access to one scope. The cache now holds only its last key/value for each weak project identity. The same real-action probe retains 141,448 bytes across distinct scopes and 78,520 bytes for the repeated-scope control, with 400 distinct signatures. Both real-action tests and all 57 independent spatial/G-code controls pass; 63 focused cache, Frame, placement and exact-program review tests also pass. This defect was introduced in the repair candidate and is separate from the eight released defects.
An independent review reproduced a further variant of the released Frame finding: selected-only User Origin at Back Right, artwork at X0 selected, X30 unused interior and X100 as the actual extent owner. Moving the unused interior object to X40 leaves the selected executable bytes, freshly prepared bounds and placement offset identical but changes both the released and earlier candidate Frame signatures. The repair now binds the actual origin-aware anchor point separately from selected output descriptors. Interior edits, non-owning extent edits and unused interior registration fixtures retain Frame; a moved anchor still invalidates it. The immutable pre-side-filter Scene, actual device/machine and two-sided setup references key a bounded last-result memo, so fresh project wrappers from selection do not recompile whole-scene CNC bounds. Resolved absent fixture bounds under Selection Origin fall through to selected compiled geometry without retaining an irrelevant unused fixture; unresolved source geometry still keeps conservative descriptors. Null and unresolved-source semantics remain consistent with output preparation. The first 65 focused tests cover all nine anchors, all five origins, both sides, current/verified origin, fixture precedence, real selection reuse and memo invalidation. No ninth released finding is counted.

The output-generator revision changes from v17 to `cnc-relief-footprints-inlay-nonzero-sketch-topology-20261009-v18` because these repairs can change executable geometry. Existing Frame policy remains: unchanged footprint and placement can retain Frame, and each Start reviews and claims the current exact program. No new licence, account or machine policy gate was added.
