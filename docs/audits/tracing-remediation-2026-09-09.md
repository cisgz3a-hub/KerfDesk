# Tracing remediation, 9 September 2026

The custom tracing engine is retained. All 20 findings from the original audit and three additional findings have independently accepted local corrections in implementation source **a258f8494801b03bb4104e1795eb7bab0f3a2e98**. This report describes that accepted behavior and its evidence limits; it is not a deployment, hardware or universal fidelity claim.

The [historical technical audit](tracing-technical-audit-2026-09-05.pdf) is an unchanged, 22-page account of the earlier source at `9209fcb33f4807ebfc1f7a55780069b6a7b0e23c`, including its inherited edits. It covers five presets and 45 control/flow rows. Its proposed corrections and old timings describe the before-state. The original **213501.jpg was unavailable**; the screenshot supplied UI evidence, not the original pixels needed to judge that artwork. The PDF retains its original 6 September cover date and references.

## What remains valuable

Line Art, Smooth and Sharp use the in-house contour route; Edge Detection uses local-contrast ink and the shared contour finisher; Centerline uses a distance field, ordered thinning and a stroke graph. ImageTracerJS remains an API fallback, not the engine behind these five UI presets. See [dispatch](../../src/core/trace/trace-to-paths.ts), [presets](../../src/core/trace/trace-presets.ts) and [architecture decisions](../../DECISIONS.md#adr-123--own-engine-trace-remove-the-potrace-derived-backend-closes-the-adr-120-blocker).

The historical independent distance oracle matched 66,237 masks / 1,093,684 pixels; raw thinning and contour reconstruction checks covered 66,132 masks / 1,059,848 pixels without recorded violations. These bounded primitive results support retaining the architecture. They do not guarantee the geometry produced after fitting, placement, filling or rasterization. No matched external-tracer experiment established that replacing the engine would improve this application.

## Tradeoffs and qualification limits

**TR-021: boundary fidelity and area are different measures.** The original Smooth notch's bounded continuous boundary error improves from about 32.19770 to 2.05376 source pixels; retained notch depth changes from 30.68251 to 63.37160 against source depth 65. Six repeated narrow-notch corpus observations nevertheless increase absolute area error: 36.7241 to 41.0325 square source pixels for Line Art/Edge defaults, and 40.3109 to 49.1363 for Sharp maximum, on source area 1,880. These are named variants, not six independent artworks. Continuous envelopes use binary64 arithmetic and declared convergence, not directed-rounding certificates. Detail below the existing 0.02 source-pixel progress floor and later fitting remain outside a universal preservation claim.

**TR-022: preserve established contacts, not arbitrary proximity.** The contact domain is an existing finite binary64 vertex exactly on a nonincident segment, including contacts across coloured paths and implicit closing edges. It excludes an intersection strictly inside both segments with no existing contact vertex. Nearby but separate lines are not welded by this rule. Exact predicates preserve source incidence before anisotropic physical mapping; retained pins survive welding, smoothing and resampling. The 144-case corpus covers 224 named endpoint contacts. The nominal 0.05 mm continuous physical fidelity budget is supported by finite numerical envelopes: the delegate's 1e-5 mm-resolution upper estimate reaches 0.05000981353323986 mm; the manager's independent upper bound reaches 0.050000000000000384 mm. These are software calculations, not machine precision or arbitrary-input proofs. The spatial index can still have quadratic work for heavily overlapping bounds; it adds no workload cap.

**TR-023: paint, geometry and motion are separate.** Complete paths, curves, placement and compiled Job objects are checked independently of SVG fill/stroke attributes. The 520 accepted-path controls replay saved outputs at a common 128 by 128 SVG viewBox; they are not 520 new image traces. Actual two-job batch tracing is separately checked. Each native observation's model/DOM pixels match; six cross-run CNC comparisons differ at the same two antialiased pixels by one RGB level despite identical SVG. Settled ready SVG is captured from the actual return before the successful dialog closes, not claimed to paint afterwards. Existing sampled SVG commands, two-decimal rounding, finite-point/color policies and visible-group counting remain.

Historical primitive, scoped regression, native dialog, software fill/raster and compiler evidence have different domains. Neither their counts nor old foreground timings establish a general performance promise. Previous fill-consumer qualification retains finite-spacing, normalization and emission-rounding limits. Generated camera frames do not certify camera calibration. The original artwork, matched reference-CAM comparison, whole-App/production-bundle visual qualification, packaged runtime and physical machine/material output remain separate.

Final combined release results and exact candidate/hosted provenance are recorded with publication evidence and the PR, rather than changing this accepted-source report after each build. No release, hosted or deployment result is implied here. Frame-first, Job Review and controller policy are unchanged.

## Primary research basis

The following sources inform the contracts; local reproductions and geometry checks establish the application's results.

- [Selinger's Potrace paper](https://potrace.sourceforge.net/potrace.pdf) separates boundary extraction, polygon construction and curve optimization. The engineering lesson applied here is to check topology and fidelity after every finishing transition, not to replace the custom engine.
- [Felzenszwalb and Huttenlocher](https://theoryofcomputing.org/articles/v008a019/) provide the distance-transform foundation; [Schneider's original FitCurves companion source](https://github.com/erich666/GraphicsGems/blob/master/gems/FitCurves.c) makes fitting tolerance explicit. Neither certifies this application's later graph processing.
- [Shewchuk's robust-predicate research](https://www.cs.cmu.edu/~quake/robust.html) explains determinant roundoff near zero. The bounded binary64/BigInt contact predicate is independently written, not Shewchuk's adaptive implementation.
- [SVG painting and fill rules](https://www.w3.org/TR/SVG2/painting.html#FillRuleProperty) distinguish stroke, fill and interior semantics. [ClipperOffset's official guidance](https://www.angusj.com/clipper2/Docs/Units/Clipper.Offset/Classes/ClipperOffset/_Body.htm) supplies winding/intersection preconditions; local region tests, rather than documentation alone, qualify the application's port and consumer.
- [WHATWG worker termination](https://html.spec.whatwg.org/multipage/workers.html#terminate-a-worker) distinguishes stopping computation from ignoring a promise result. [WAI modal-dialog guidance](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) supports focus and Escape behavior, without establishing complete accessibility conformance.
- [LightBurn's current Trace Image guide](https://docs.lightburnsoftware.com/latest/Reference/TraceImage/) supplies control and workflow expectations. It was a documentation reference, not an executed fidelity or performance comparator.

Only this report and the unchanged historical PDF are publication documents for the final preparation step. Bulk evidence, private machine paths, browser profiles, caches, failures and donor checkouts remain locally preserved by the audit manager. The historical PDF retains its original evidence references; it is not a portable replacement for that complete local archive.
