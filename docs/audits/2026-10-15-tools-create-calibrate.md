# Tools audit: Create & measure, Calibrate, Settings and two ungrouped commands

Date: 15 October 2026. This is a source, design and automated-test audit of the 19 commands in these menu groups, plus Box Fit Test and AI Assistant, which appear under Other. Live computer-use evidence is maintained by the integrating audit; **this document does not certify browser interactions, packaged desktop, physical camera accuracy, real provider requests or machine/material performance**.

## Outcome and repaired defects

The latest automated results for the assigned features comprise **165 files and 1,359 passing tests**, with no failures in the latest result for each file. The machine-readable ledger is [2026-10-15-tools-create-calibrate-tests.json](2026-10-15-tools-create-calibrate-tests.json). Counts include existing suites rerun for this audit and the new regression/stress tests. They are not 1,359 independent end-to-end operator workflows.

1. **Tangent Circle:** the fixed XY determinant incorrectly discarded every collinear-centre case, including unequal circles with finite tangent solutions. Squaring global coordinates also lost precision for small artwork translated far from zero. The solver now translates/scales locally and selects the strongest two-coordinate pivot, including the radius coordinate. Each candidate is checked against all three tangency equations. Invalid/nonfinite radii are rejected. The dialog describes internal tangency accurately; an internally tangent output circle need not enclose an input circle. Empty-result wording no longer asserts mathematical impossibility.
   - Reproduced three failing regression cases before repair. The final suite includes eight tests, with a 256-case construction sweep across rotations and scales from 0.0001 to 10,000, collinear unequal radii, translation to ±100,000,000, and invalid numeric inputs.
2. **Material Test and Interval Test:** metadata and speed labels reported a decimal requested/capped feed even though output represents feeds of at least 1 mm/min as floored integers. Both now share the existing G-code feed representation function. Requested speed is retained separately. Tests cover 1234.9 → 1234, a 1234.9 profile ceiling → 1234, and the valid fractional ceiling 0.25 → 0.25.
3. **Print and Cut:** `solveTwoPointRegistration` returned `ok: true` for NaN, infinite and overflowing coordinates. Four failures were reproduced before repair. It now returns an explanatory failure for nonfinite coordinates, overflowing spacing, or an unrepresentable transform. This is numeric geometry validation, not an extra policy gate. Existing unusual-but-representable scale/rotation cases remain warnings. ADR-443 and ADR-565 were inspected before editing.
4. **Stress evidence:** added a 720-direction Measure sweep confirming translated distance and 45-degree Shift snapping, plus maximum-size calibration generation: 400 Material Test cells on both speed-axis choices, 20 Interval swatches and 10 Scan Offset swatches. Requested counts of 10,000 or 1,000,000 remain bounded and preserve endpoint settings.

The broad test run started before the registration repair and captured its four deliberately introduced regression failures against the old loaded module. The subsequent affected regression run passed all 100 tests. The ledger selects the later result per filename and preserves the report names and timestamps; it does not hide the earlier failures.

## Reproduction and limitations

The executed command batches are recorded by report name in the JSON ledger. They used `node node_modules/vitest/vitest.mjs run ... --maxWorkers=2 --reporter=json --outputFile=...`. Tests run in jsdom, use existing mocks/simulators where appropriate and do not move hardware. The full raw reports are under `artifacts/tools-create-calibrate*.json` in this checkout. The compact checked-in ledger retains every executed assertion title/status and per-file timing without treating those timings as controlled performance benchmarks.

Computer-use rows must be supplied by the integrating audit. Every tool still needs an explicit distinction between “opened”, “completed a representative workflow”, “stress-tested in the UI”, “native desktop verified”, and “hardware/material/provider qualified”. A menu click alone proves none of the latter four. This audit provides research and test evidence, not a blanket “all tools designed correctly” certification.

## Autosave preparation liveness repair

The development-server direct audit observed Scan Offset and File New failing to finish after choosing Don't Save during module/worker startup stalls. In the locally built renderer, Scan Offset subsequently opened immediately after the same dirty-mode-change/Don't Save path, generated its five-swatch baseline (10 objects, six operations), and undid to zero objects/operations. The root agent also drew three noncollinear 20 mm circles, reviewed eight Tangent Circle solutions, added the first (105 mm diameter) and undid from four objects/operations to three. Screenshots and exact direct results are in the master register. Source review found an independent reproducible liveness defect: autosave worker preparation had no deadline, and its durable write queue could indefinitely delay the ordered clear used by explicit discard. That defect is not asserted as the proven cause of the development-server stalls.

Two focused pre-fix tests failed: a silent worker was not terminated after 60 seconds, and a queued autosave remained unsettled behind another owner. The raw pre-fix report also contains an experimental interactive-preemption expectation that was rejected after reviewing ADR-598; it is not counted as a product defect. Healthy active autosave intentionally remains non-preemptible.

The repair bounds queued plus active preparation to 60 seconds. Expiry terminates only the owned worker before releasing its reservation, or removes only its queued reservation. It returns the ordinary preparation failure; no empty snapshot, synchronous retry, forced discard, or revision-guard bypass is introduced. An event-loop stall can delay delivery of the deadline callback; this is a worker-preparation deadline, not a bound on IndexedDB or session-lock operations.

Post-fix verification passed **19 tests in two files** (`autosave-preparation-client.test.ts` and `autosave-durable-preparation-order.test.ts`, report `artifacts/tools-create-autosave-after.json`). Coverage includes healthy non-preemption, silent-worker expiry, queued expiry without retiring another owner, ignored late replies, committed recovery preservation, ordered explicit clear, and later valid retry. ADR-598 Amendment 1 and WORKFLOW document the recovery boundary. These results are included in the updated assertion ledger.

The 21-command browser harness was adapted to reuse a loaded page and to reset each document through ordinary File Open. Final cold development-server attempts in the coordinated audit still failed before the app mounted; the coordinator stopped further cold retries. **No completed creation-suite browser pass is claimed.** Root-agent direct computer-use results and screenshots are recorded separately per command in `2026-10-16-tools-quality-register.md`.

The final autosave source and two test files, plus the 21-command creation browser harness, passed targeted ESLint. Prettier was applied to the changed TypeScript files, and `git diff --check` passed. Aggregate TypeScript/static checks are maintained by the integrating audit.
