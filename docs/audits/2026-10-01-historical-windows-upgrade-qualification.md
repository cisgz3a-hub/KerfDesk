# Historical Windows upgrade qualification

The previous production lane qualified a fresh installed launch, import/save and uninstall on a throwaway smoke profile. The Preview full scenario compared candidates built from one source and used CDP, which commercial builds forbid. Neither established retention when a customer upgrades between published production versions.

`qualify-desktop-upgrade.yml` authenticates the immutable public 1.0.2 and 1.0.3 installers by default. The manual dispatch can select another published pair. The signed manifest's requested version, stable channel, exact byte count, SHA-256 and pinned signature must match; the installed release identity, pinned licence configuration, renderer version and disabled automatic updater must agree. Historical legal and dependency notices are checked for presence, rather than compared to a newer source tree. The download helper never executes an installer. It retains the original signed manifests, public receipts and archive listings.

`qualify-windows-installer.ps1 -Scenario HistoricalUpgrade -PackageKind CommercialUnsigned` executes NSIS only on a disposable GitHub-hosted Windows VM with no existing KerfDesk installation, profile, shortcut or process. It installs into its owned runner directory, verifies registration, shortcuts, file association and executable/ASAR hashes, and launches the ordinary installed app with its normal `%APPDATA%\laserforge` profile. The normal-profile driver independently enforces the hosted-runner restriction and records ownership for subsequent launches. It uses no smoke profile, CDP, injected renderer script or modified application archive.

The shipped app's Windows accessibility provider exposes ordinary UI controls. The driver selects Dark appearance, Spacious density and a recent-project limit of 17. It saves a machine named `Upgrade retention fixture` with a 321 × 234 mm bed, imports a 20 × 12 mm SVG through the real native Open dialog and saves a real `.lf2` through Save As. The next launch must offer that saved machine. The driver applies the offer and reads its fields before opening the retained project, so the project's own device cannot mask corruption of the app-level profile. It then discards only that owned blank project's machine edit through the normal Don't Save confirmation, opens the retained file and separately checks its machine. Preferences and machine fields are read through their real controls. Saved project geometry, layers, workspace, job setup, device and machine configuration are compared independently on disk.

The scenario checks five launches: original creation, original restart, upgrade, same-version reinstall, and reinstall after uninstall. It preserves and checks the original project SHA-256 and a random profile sentinel through installer operations. Each reopening saves a second file and compares its content to the retained original. It checks the Free edition before each phase, never activates a paid licence or trial, and closes the owned process normally after saving. Real common-dialog ownership is checked against the expected executable, PID, session and process ancestry. Failure retains diagnostics and blocks the future release gate.

The unsigned release planner exports the authenticated previous version and source. `release-desktop-unsigned.yml` downloads that baseline and requires this scenario against its newly built exact-source candidate before publication. It retains the existing 20-PR policy, explicit early-release override, fresh-install and ASAR security checks, exact-source rules and guarded publication. A first release has no baseline and still runs fresh-install qualification. The standalone historical workflow can close an older pair's evidence gap without publishing or changing the public update pointer.

Review the native `qualification.json`, all five driver `result.json` files, original signed manifests, project files, process/dialog receipts and screenshots before claiming a pair passed. Local control discovery and authenticated extraction alone are not historical installer proof. A green source check is not a native qualification result.

The evidence is limited to the hosted runner OS and account. Free state is the current licence scenario; paid credential or trial retention requires a separately authorised synthetic credential scenario. Consumer Windows, standard-user UAC, SmartScreen, signed automatic updates and physical hardware are not qualified by this workflow. No connected machine is operated.

The implementation uses the documented [Windows UI Automation Invoke pattern](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.invokepattern.pattern?view=windowsdesktop-10.0) and [Electron accessibility support](https://github.com/electron/electron/blob/main/docs/tutorial/accessibility.md). `--force-renderer-accessibility` exposes normal accessibility controls; it does not restore production DevTools privileges.
