# Tools audit: Image, Variable data, Trace and Bitmap

Audit started 15 October 2026 and continued on 16 October (Asia/Shanghai). Source baseline: `f7e2a36895b67cfa33be03c16e6c19e7c6722d14`, with the scoped repairs and regression tests in this working tree. Inventory is the actual `src/ui/commands/app-menu-groups.ts` menu: 14 commands. This report records source, research, automated and direct computer-use evidence. Direct testing exercised all 14 entries: 11 substantive representative workflows completed, two exports reached an unavailable native file-picker boundary, and Multi-File Trace showed its expected Pro entry gate. This is local bundled renderer evidence, not packaged desktop or hardware qualification.

## Findings and repairs

1. **Fixed: successful blank/partial Save Processed Bitmap.** Its synchronous bitmap builder substitutes white pixels for absent, malformed or truncated embedded luminance. The export wrapper previously accepted that as a successful image. It now validates the processing pixels before encoding and reports missing or malformed data with explicit Image Studio → Apply recovery advice. Recovering only the export would disagree with the current executable-output source, so the repair preserves that ownership boundary. Tests cover absent, malformed, truncated and invalid-padding luminance, and missing actual pixels. This changes image export only; it does not change the executable-output compiler.
2. **Fixed: decoded bitmap resource leak on failed Save Original Image.** Re-encoding used to close its `ImageBitmap` only after a successful draw. A missing canvas context or failed draw skipped cleanup. A `finally` block now closes the bitmap in either case. Both failures have regression tests; no successful file is written.
3. **Open performance qualification: Crop/Flatten.** Both commands share `cropMaskedRasterImage`, which traverses the source grid twice for masking and allocates complete probe/source/output arrays. The 2,097,152-pixel correctness stress below passes. The routine still runs its pixel loops synchronously, has no cooperative cancellation, and is not evidence of responsive maximum-size editing. Import permits a burn source of up to 32 million sampled pixels; maximum-size browser latency and peak memory are not qualified by this audit. No new arbitrary image rejection was introduced.
4. **Open performance qualification: Adjust Image.** Display canvases cap the longest edge at 420 pixels, but the processed preview applies nonlinear adjustment on the full source before resampling. This preserves the correct operation order; it does not make full-source edits cheap. Maximum-size slider responsiveness needs browser timing.
5. **Evidence limits.** Passing model/store/render tests is not native desktop or physical engraving qualification. Trace quality varies with input, preset and output scale; neither a paper citation nor the current regression corpus establishes correctness for every image.
6. **Fixed: Adjust Image required two Undo actions for one OK.** The browser workflow changed Brightness to 17, accepted the dialog and pressed Undo; brightness remained 17. `CommandShell` had called the image action and layer action separately, each creating history. The image action now accepts the dialog's restricted operation settings and commits both in one guarded update. Shared-layer behaviour is retained. The store regression checks the combined values, one-step exact-scene restoration and Redo.

## Research checked against the implementation

Sources were retrieved during this audit, not inferred from code comments. External product behaviour is a comparison; the repository's accepted decisions govern intentional differences.

| Ref | Primary source | Criterion used |
| --- | --- | --- |
| R1 | [LightBurn image masking](https://docs.lightburnsoftware.com/2.0/Reference/ApplyMaskToImage/) | Editable masking versus permanent cropping; flattening removes the mask shape. KerfDesk deliberately retains a locked or still-referenced mask, as ADR-480 records. |
| R2 | [LightBurn Adjust Image](https://docs.lightburnsoftware.com/latest/Reference/AdjustImage/) | Tone controls and visible processed preview, image versus operation setting ownership. |
| R3 | [LightBurn Variable Text](https://docs.lightburnsoftware.com/latest/Reference/VariableText/) | Bake freezes the currently evaluated value rather than advancing serials. |
| R4 | [LightBurn Trace Image](https://docs.lightburnsoftware.com/latest/Reference/TraceImage/) | Raster-to-vector approximation, image-quality limits, preservation of fine features. |
| R5 | [Selinger, Potrace algorithm](https://potrace.sourceforge.net/potrace.pdf) | Separate contour extraction, polygon approximation and smooth curve fitting; reference reasoning only, no outside implementation copied. |
| R6 | [WHATWG ImageBitmap](https://html.spec.whatwg.org/multipage/imagebitmap-and-animations.html) | Explicit bitmap resource ownership and `close()` lifecycle. |
| R7 | [Gwosdek et al., extended box filtering](https://www.mia.uni-saarland.de/Publications/gwosdek-ssvm11.pdf) | Three-pass extended-box Gaussian approximation, fractional edge weight and variance. Current implementation has an independent exact-kernel oracle. |
| R8 | [LightBurn Convert to Bitmap](https://docs.lightburnsoftware.com/latest/Reference/ConvertToBitmap/) | Raster density, preview and transformation semantics. KerfDesk's narrower density range is an explicit model difference, documented in `bitmap-conversion-plan.ts` and ADR-029. |
| R9 | [W3C SVG clipping/masking](https://www.w3.org/TR/SVG11/masking.html) | Coordinate-space and alpha/luminance reasoning; KerfDesk closed-shape geometric masks are not represented as general SVG alpha masks. |
