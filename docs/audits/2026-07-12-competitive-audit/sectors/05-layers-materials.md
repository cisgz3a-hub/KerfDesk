### State of play

This is LightBurn's home sector. The Cuts/Layers window is the daily-driver surface the whole roster is measured against, and LightBurn holds or shares the top score in six of seven categories: the palette-layer model where a color click assigns full cut settings (5.1), the broadest documented per-layer parameter set in the roster (5.2), eleven drag-reorderable sub-layers per layer (5.3), a .clb material library with Assign-vs-Link semantics, merge, and network sharing (5.5), 'Sort Cuts Last' auto-ordering (5.6), and an inline-editing table with copy/paste and context menus (5.7). All of that is [OFF] official-manual evidence — no hands-on run occurred — but for existence-level breadth claims the manual is sufficient under §7.2.

KerfDesk's architecture deliberately mirrors that reference, and the skeleton is genuinely there: color-keyed layers auto-created per unique stroke color with LightBurn's exact Show-vs-Output split (5.1), a deep typed per-layer settings union spanning laser and a parallel CNC block (5.2), N full-settings sub-layers compiled after the primary (5.3), and a provable guarantee LightBurn only implies — the visible layer order IS the execution order, pinned by an output-parity test across prepared output, preview, G-code, and estimate (5.6, ADR-040). KerfDesk lands 6–7 across those categories: daily-drivable everywhere, behind the leader everywhere. The recurring deficit pattern is ergonomics and breadth at the edges, not model correctness: no fixed palette strip for one-click assignment; no Z-step, perforation, dot mode, cut-through delay, or ramp among the layer parameters (with no scope ADR recording the absence); a sub-layer dialog that silently discards a dead 'Visible' checkbox; single-step up/down arrows where everyone else drags; and a settings rail with silent clamps and a Delete button that removes artwork against its own workflow doc.

The one category where KerfDesk plausibly leads the reference is per-object overrides (5.4). LightBurn's Shape Properties gives per-shape Power Scale only; KerfDesk's `operationOverride` forks the *entire* settings block per object, and the compiler buckets overridden objects into synthetic effective layers so preview, G-code, and estimate provably agree — plus a separate powerScale that matches LightBurn's feature one-for-one. That is an 8-vs-6 lead over LightBurn, though it only ties MillMage and XCS's per-object-native models, which get full per-shape parameter sets by construction. The caveats are real: the override model has no ADR (an unrecorded LightBurn divergence per §5.6), and overrides are invisible in the layer list unless the object is selected.

The material library (5.5) is KerfDesk's clearest structural loss and splits the roster in an interesting way. LightBurn has the strongest *mechanics* (.clb format, linked presets, merge, shared network libraries) but famously ships empty — a recurring new-user complaint. xTool Studio inverts that: the official EasySet library bundles per-machine, per-material presets and takes the roster's second spot despite its xTool-only scope; Easel likewise ships built-in recommendations per machine/material/bit. KerfDesk has a sound deterministic native format (ADR-045), a multi-library manager with a wizard (ADR-093), and a now-fixed warn-don't-block device-mismatch flow — but no .clb import, no linked presets, no community or manufacturer content, and starter presets for exactly one machine (7 entries). For a LightBurn switcher, the missing .clb import means their accumulated material knowledge cannot follow them.

The rest of the roster confirms the sector's shape rather than contesting it. MillMage ports LightBurn's ergonomics to a CNC operations model (organizational layers, ops attached to shapes, drag-reorderable ops table, operations library) and scores a consistent 5–8 with zero community quality data — every MillMage cell is docs-only and its ratings are soft. xTool Studio's model is per-object with parameter-free layers: strong where that model is native (5.4, EasySet, Auto Planning cut ordering) and weak where layers are supposed to carry meaning (5.1, and no stacked ops found — [INF]). LaserGRBL simply does not have this sector: no layers, no per-layer settings, no library, no panel — six zeros and a 2, all for a product that, as a laser sender people do real work with, must still be scored against the category rather than excused from it. Easel's per-shape depth/cut-type model plus bundled cut settings serves its beginner persona (5.4, 5.5) but has no settings-layer model, no stacked ops, and — per its own community — no cut-order control at all.

For personas this sector weighs 7/100 (LightBurn-switcher hobbyist), 6/100 (CNC beginner), and 8/100 (small production shop). KerfDesk's sector mean is ≈6.7 vs LightBurn's ≈9.0 — the model parity is real, but every daily touchpoint (palette strip, drag reorder, library content, panel polish) still reads as a competent clone one generation behind the original.
