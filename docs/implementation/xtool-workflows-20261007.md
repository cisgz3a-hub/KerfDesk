# xTool Studio workflow implementation

7 October 2026. Implementation branch: `codex/xtool-workflows-20261007`, based on `origin/main` `76b5ff53e3be7df6c160a8b26820e61188595f08`.

This is the implementation list following the broad Studio audit. Changes reuse KerfDesk's existing design, recipes, CAM and controller foundations. Device-neutral workflows apply to laser and CNC; accessory operations require a declared capability and a documented, qualified adapter for the particular device. "All machines" is the portability target, not evidence that every controller implements an accessory protocol.

## Delivery constraints

- The latest Frame/Start ownership contract (ADR-565), existing licence admission and CNC settings ownership are preserved.
- Changes are isolated from the dirty primary checkout. The implementation is prepared for the authorised commit and pull request; merging, deployment, provider modification and machine operation require their own authorisation.
- The statuses below describe the delivered software and its boundaries. Physical manufacturing, packaged installations and hosted services require separate evidence.
- Hardware and hosted AI items cannot be qualified from source tests. General interfaces must not expose unsupported actions as working features.

## What changed and what remains

The implementation keeps KerfDesk's original CAM, operation bindings, CNC tools, recipe revisions and controller handoff. It changes the workflows around them: material tests now lead to saved evidence, design edits have inspectable previews, arrays retain their intent, and production records retain their allocated identity. These are the transferable strengths found in Studio. A vendor-specific machine wizard or automatic accessory action would undermine the stated portability target unless its adapter is documented and tested.

Project schema 14 adds durable compound operands and hierarchy presentation ranks to schema 13's sheets, manifests, retained arrays, names/parents, text frames and fixtures. Older projects migrate without acquiring those features. Material-library schema 3 stores experiments and continues to read versions 1/2. Inactive sheets, production seeds/variants and array source/baseline snapshots share an iterative 50 million character archive budget. Import and authoring both enforce it, including combined/nested archives. Archived compounds must reproduce their saved result from retained sources; invalid geometry or semantic drift is refused without rewriting archive strings. Retained compound operands count against the existing scene budget. Browser admission checks inspect the same archives using the existing Pro rules.

Acceptance remains limited where the table states a boundary. The implemented AI provider and FluidNC/GRBL protocol contracts have source, fake-provider and loopback/simulator evidence. Actual API-account behavior, installed packaging, controller motion/sensor accuracy, firmware recovery, conveyors and physical output require their own evidence. These limits are explicit in the UI and [ADR-571](../decisions/ADR-571-retained-design-and-explicit-desktop-adapters.md).
